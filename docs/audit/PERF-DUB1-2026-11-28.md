# Laporan Optimasi Performa dub1 — 2026-11-28

Branch: `perf/dub1-region-batch-queries-and-auth-chain`, dibuat dari `main` setelah PR #26 (`9a95175`).

## Perubahan

- `vercel.json` menetapkan `regions: ["dub1"]` dan tetap mempertahankan `crons: []`; jadwal otomatis eksternal tidak diambil alih Vercel.
- Beranda `/` mengubah lima query bootstrap browser menjadi satu `getHomeBundleAction` dengan `Promise.all` server-side.
- `/laporan` mengubah tiga query bootstrap menjadi `getReportBundleAction`.
- `/kehadiran` mengubah tiga query bootstrap menjadi `getAttendanceBundleAction`.
- Cache key baru bersifat session + role scoped. Key lama tetap dipertahankan dan invalidation mutasi menjangkau bundle baru, sehingga check-in, submit laporan, dan perubahan policy tetap menyegarkan data.
- `resolveIdentity` memakai `auth.getClaims()` untuk JWT terverifikasi, dengan fallback `getUser()` bila claims tidak tersedia/error. `React.cache()` yang sudah ada tetap menjadi memoization request-level; role berasal dari seluruh `roles[]`, bukan `member_type`.

## Dampak yang dapat diverifikasi dari kode

| Halaman | Sebelum | Sesudah | Dampak |
|---|---:|---:|---|
| `/` | 5 request bootstrap | 1 request bundle | 4 putaran browser berkurang; query server berjalan paralel |
| `/laporan` | 3 | 1 | 2 putaran browser berkurang |
| `/kehadiran` | 3 | 1 | 2 putaran browser berkurang |

Bundling mengurangi round-trip browser dan waterfall; jumlah query domain internal tetap dipertahankan agar RLS/guard yang sudah ada tidak dilewati. Pengukuran latency p50/p95 produksi belum dilakukan.

## Vercel

Operator dapat memverifikasi Function Region `dub1` di Dashboard Vercel dan memeriksa header `x-vercel-id`, yang diharapkan berbentuk seperti `sin1::dub1::...`. Tidak ada cron internal Vercel yang diaktifkan.

## Keamanan dan batasan

Tidak ada perubahan pada `src/modules/reports/actions.ts`, `src/lib/db/reader.ts`, migrasi trigger `trg_audit_logs_append_only`, atau `PERMISSIONS.md`. Bundle tetap memanggil Server Action yang sama, guard yang sama, dan RLS yang sama. Tidak ada migrasi database atau perubahan permission.
